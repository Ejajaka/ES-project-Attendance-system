# CONTEXT.md — Shusseki domain model

This file is the canonical glossary for the Shusseki continuous-attendance system.
Module names and seams should be named after the concepts defined here. When you
sharpen or add a term, update this file inline.

## Modes

- **Transmitter (Soshin)** — the fixed, room-side device. Sole transmitter of
  the ultrasonic rolling code. Advertises/scans BLE, hosts the fixed open
  `atlas` network (no password) — the ESP32 room node is the AP — and performs
  a fast local pre-check of rolling codes. It is *not* a person; it is a phone
  or node left in the room. UI label: **TRANSMITTER**.
- **Receiver (Jushin)** — the phone a person carries to prove presence. Joins
  the open `atlas` network, reports its own BLE interface + observed
  transmitter BLE signal, reports WiFi signal info, and **listens only** for
  the transmitter's ultrasonic rolling code. It never transmits ultrasound.
  Performs an on-device biometric check at start/end of attendance. UI label:
  **RECEIVER**.

> The wire/report field values remain `soshin`/`jushin` (protocol compatibility);
> every human-readable surface says TRANSMITTER/RECEIVER first, brand second.

## Core concepts

- **Device** — a physical phone running the app in one Mode, identified by a
  stable `deviceId` (persisted UUID).
- **Room** — a physical space under study, with a `roomId` and a known set of
  Soshin nodes.
- **Session** — one controlled data-collection run in a Room, with a start/end
  time and an associated manual **GroundTruth** headcount.
- **Modality** — one of `ble`, `wifi`, `ultrasonic` (and the derived `fused`).
- **Observation** — a single per-modality reading reported by a Device at a
  timestamp (raw sensor values, never a final decision).
- **Report** — the envelope a Device sends to the Server: deviceId, mode, roomId,
  sessionId, timestamp, and the Observations it collected.
- **RollingCode** — a TOTP-like code generated by the Soshin from a shared
  secret and the current time step, broadcast as an ultrasonic tone. The Server
  is the final authority on validity; the Soshin's local check is only a pre-check.
- **Confidence** — a presence probability in `[0,1]` produced per Modality and
  for the Fused result.
- **GroundTruth** — the manually established headcount for a Session, the
  benchmark every Modality is compared against.
- **CombiningRule** — the rule used to merge several BLE/WiFi node readings into
  one per-modality Confidence (e.g. `max`, `avg`, `best`). Default: `max`
  (a single strong node reading implies "within walkable distance of the room").

## Roles in the pipeline

```
Device (transmitter/receiver) --Report--> Server --ingest--> Observations
                                            |
                                            v
                                  per-Modality Confidence
                                            |
                                            v
                                       Fused Confidence  --compare--> GroundTruth
```

## Boundaries that must not leak

- A Receiver (Jushin) **never** emits ultrasound. The Transmitter (Soshin) is
  the sole source.
- Client-side RollingCode checks are an optimization, not a security boundary;
  the Server verifies every code.
- BLE/WiFi are treated as *approximate, supplementary* room-proximity sensors,
  not precise localizers.

## Link stats

- **LinkSummary** — per-device connection health across `ble`, `wifi` and
  `ultrasonic` (`connected` / `degraded` / `lost` + 0..1 quality). Computed by
  `summarizeLink` on both the receiver (its own link) and the server (every
  device in the session, for the transmitter's monitor).
- **HotspotAnnouncement** — legacy two-phone fallback: the transmitter
  publishes its live `AndroidShare_XXXX` SSID/passphrase to the session. The
  atlas deployment does not need it, because receivers join `atlas` directly.
- **RoomPreset** — one of three fixed room identities (roomId, sessionId, SSID
  hint, rolling secret) selectable on the home console.
