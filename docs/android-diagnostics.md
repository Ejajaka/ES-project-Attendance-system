# Android build & diagnostics notes

Started on `fix/release-apk`; kept up to date as the toolchain moved to npm.
Goal: a **self-contained release APK that actually renders** on the emulator.

## The original problem

`unable to load script` when installing the **debug** APK. A debug build
intentionally omits the JS bundle and expects Metro at runtime. The fix is a
**release** build that embeds the bundle.

## Building a self-contained release APK (npm toolchain)

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk
export PATH="$JAVA_HOME/bin:$PATH"          # Gradle 8.10 needs Java 21, not 25
cd app
npx expo prebuild --platform android        # regenerates gitignored app/android
cd android
./gradlew assembleRelease
# → app/android/app/build/outputs/apk/release/app-release.apk (≈61 MB)
```

The release build:
- bundles JS via `expo export:embed` (Metro `bundleCommand = "export:embed"`),
- signs with the debug keystore (preconfigured), and
- embeds the Hermes bytecode at `assets/index.android.bundle`.

## The `expo.core.ExpoModulesPackage` compile error — FIXED (no stub)

`expo-modules-autolinking@2.0.8` emits `import expo.core.ExpoModulesPackage;`
into the generated `PackageList.java` (it ignores the expo package's
`packageImportPath` and falls back to the `namespace "expo.core"` from
`expo/android/build.gradle`), but the class is actually generated as
`expo.modules.ExpoModulesPackage`, so `:app:compileDebugJavaWithJavac` fails:

```
PackageList.java:14: error: cannot find symbol ... location: package expo.core
```

**Fix (in repo, durable):** the project-level `app/react-native.config.js`
overrides the `expo` dependency's Android package import to
`expo.modules.ExpoModulesPackage` (both the legacy `n` key consumed by expo's
autolinker and `packageImportPath` consumed by the community CLI). Earlier
drafts suggested hand-adding `app/android/app/src/main/java/expo/core/
ExpoModulesPackage.java` as a stub — that is **obsolete**: `app/android/` is
gitignored and regenerated by `expo prebuild`, so the stub was wiped on every
prebuild. Use the `react-native.config.js` override instead.

## Environment prerequisites (this machine)

- **npm** (Node **24.18.1** verified against Expo SDK 52; pin an older Node via
  `n` only if a future Arch `nodejs` bump breaks the Expo CLI).
- JDK 21 at `/usr/lib/jvm/java-21-openjdk` — set as `JAVA_HOME`.
- Android SDK at `/opt/android-sdk` (chown'd to user), `platforms/android-35`,
  `build-tools/35.0.0`, `platform-tools`, `emulator` +
  `system-images;android-35;google_apis;x86_64`, AVD `shusseki`.
- `expo@52.0.49` + `expo-modules-core@2.2.3` (npm keeps them consistent).

## Emulator diagnostics (done)

```bash
adb install -r app-release.apk
adb shell am start -n com.shusseki.app/.MainActivity
adb logcat -d | grep ReactNativeJS
adb exec-out screencap -p > verified.png
```

Known emulator gotchas (details in `arch-installation-quirks.md`):
- The userdata disk check is a hard **7.4 GB**; config/flag overrides don't
  shrink it. Free real disk until it fits.
- `pkill -f qemu-system` self-matches the launching shell; kill by PID /
  exact name instead.

## The old "black screen" blocker — RESOLVED ✅

Earlier the release APK launched but showed a black screen:

```
E ReactNativeJS: TypeError: Cannot read property 'EventEmitter' of undefined
E ReactNativeJS: Invariant Violation: "main" has not been registered.
```

Diagnosis then: the hand-assembled Expo app never installed `globalThis.expo`
(Bridgeless/expo-modules-core JSI host wiring). After rebuilding the app as a
proper Expo project and moving the repo to npm, that crash is **gone** —
the release APK now renders the Shusseki UI on the emulator (verified via
`uiautomator dump`: "Shusseki", "RUN AS SOSHIN (ROOM)", "RUN AS JUSHIN
(PHONE)").

**New "main has not been registered" cause found during verification — FIXED:**
`app/src/App.tsx` called `crypto.randomUUID()` at module load; Hermes has no
global `crypto`, so the bundle threw before registration. It now falls back to
a pseudo-random id (see commit `b6ba8a1` and `arch-installation-quirks.md`
troubleshooting #5).
